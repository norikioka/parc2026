PARC2026 進捗サマリー

2026年7月28日〜29日の作業まとめ。目標: 予選(8月中旬〜)を確実に突破する。

1. プロジェクトのセットアップ

ローカル(Python 3.12/uv管理)とColabを連携させる開発環境を構築。戦略ドキュメント(docs/strategy.md)、 環境構築手順(docs/env_setup.md)、進捗チェックリスト(docs/progress.md)を整備し、 GitHub(github.com/norikioka/parc2026)で管理。

効果: 作業内容が全てドキュメント化・バージョン管理され、後から見返せる状態になった。

2. 採用モデルの選定

候補7モデル(OpenVLA-OFT / π0 / π0.5 / Nora / WorldVLA / UniVLA / RIPT-VLA)を比較調査した上で、 実際にインストールした開発環境(LeRobot)にそのまま乗るPi0.5を採用(LIBERO公式再現値: 平均97.5%)。

3. Colab無料枠でのOOMクラッシュ調査

問題: Pi0.5モデルのロード時に毎回メモリ不足でクラッシュ(exit code 137 = OOM Kill)。 bfloat16化・コンパイル無効化・非同期無効化など複数の対策を試すも解決せず。

Codex CLI(別モデル)にソースコードを直接調査させ、2段階の調査で根本原因を特定:

調査判明した原因
1回目チェックポイント読み込みがCPU RAM経由(7.47GB)。device="cuda"指定で軽減可能と判明→パッチ適用
2回目パッチ後も再発。モデル生成自体がCPU上でfloat32の実体を構築してからGPU転送する実装で、 ここだけで約10GB消費。LeRobot側のコード改修(meta device初期化)が必要で、CLIフラグでの回避策は無いと判明

効果: 「なぜ動かないか」を推測ではなく実際のソースコードで確定でき、 コード改修という深追いをせず環境移行を選ぶ、という意思決定が根拠を持って行えた。

4. RunPodへの移行判断

Colab Pro/Pro+・Kaggle・GCP無料枠なども比較した上で、今回の利用パターン(2〜4週間・週10時間程度)では 従量課金のRunPodが最安、かつ直接SSH自動化のおまけ付きと判断。

選択肢この期間の費用目安備考
Colab Pro月額$12固定自動化なし(コピペのまま)
RunPod$6〜20(使った分のみ)直接SSH操作可能

5. RunPod環境構築

完了 GPU Pod起動: RTX 3090(24GB VRAM・125GB RAM・$0.51/時間)
完了 SSH直接接続を確立(専用鍵作成・接続確認済み)
完了 リポジトリをpublic化してPod上にclone(トークン管理不要に)
完了 LeRobot本体(pi/libero extras)インストール、torch+CUDA動作確認
進行中 robosuite用のEGL(GPU描画)システムライブラリを追加インストール中

効果: RAM 125GBの環境に切り替えたことで、Colab無料枠で起きていたOOMクラッシュの 発生条件そのものが解消される見込み。加えて、これ以降はColabでの「コピペで結果を貼ってもらう」 往復作業が不要になり、私が直接コマンドを実行して進められるようになった。
